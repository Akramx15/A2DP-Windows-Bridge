# Updating this fork when upstream publishes a release

This fork carries one feature over `SeiyaFunaokaJP/A2DP-Windows-Bridge`: the XM6 spatial
engine (Sony 360RA chain + Upmixer) on Windows. Everything here exists so a new upstream
tag costs one command instead of a rediscovery session.

## The one command

```powershell
python tools/xm6/sync_upstream.py            # newest upstream tag
python tools/xm6/sync_upstream.py --tag v2.0.2-beta.11
```

What it does, in order:

1. Refuses to run on a dirty tree or on a branch other than `feat/xm6`.
2. `git fetch upstream --tags`.
3. Cuts `upstream-sync/<tag>` from `feat/xm6`.
4. `git merge --no-ff --no-commit <tag>`.
5. Resolves the two conflict classes that are mechanical, and only those:
   - `app/lang/*.json` — language files are key/value maps; ours and upstream's keys are
     unioned, ours wins on a shared key. Hand-merging eight files is how keys get lost.
   - `app/src/ui/src/ipc/bindings/*.ts` — generated by `ts-rs`; ours are regenerated from
     the merged Rust protocol instead of merged as text.
6. Leaves any other conflict in place, lists the files, and exits non-zero. Nothing is lost.
7. Runs the gates: `cargo +stable-x86_64-pc-windows-gnu check --workspace`,
   `pnpm exec tsc --noEmit`, `pnpm exec vitest run`, `python tools/check_lang.py`.
8. Commits the merge and prints the tag to create: `v<upstream-tag>-xm6.<n>`.

Options: `--dry-run` (fetch and report what would conflict, change nothing), `--no-gates`,
`--keep` (leave the merge branch checked out), `--push` (push the branch and the tag).

## Branch model

| Branch | Meaning |
|---|---|
| `main` | exact mirror of `upstream/main`. Feature work never lands here. |
| `feat/xm6` | the permanent feature branch — this fork's product. Never rebased, never force-pushed. |
| `upstream-sync/<tag>` | short-lived merge branch, deleted after the merge lands on `feat/xm6`. |

The merge direction is always **upstream tag → feature branch**. The reverse (rebasing the
feature on the tag) rewrites history every release and loses the answer to "which upstream
is this build from". The upstream lineage stays readable with `git log --first-parent`.

Releases are annotated tags on the merge commit: `v2.0.2-beta.10-xm6.1`.
`Cargo.toml` deliberately keeps the upstream version, so it never conflicts.

## When the script stops on a conflict

Reproduce, then resolve by hand — and afterward teach the script if the conflict was
mechanical:

```bash
git status --short                 # unmerged paths
git diff --name-only --diff-filter=U
```

| File | Usual resolution |
|---|---|
| `app/src/ui/src/ipc/bindings/*.ts` | `git checkout --theirs -- <file>` then `cargo test -p ipc export_bindings` |
| `app/lang/*.json` | run the script's `--fix-lang` path, or merge the keys with `python tools/xm6/sync_upstream.py --fix-lang` |
| `app/src/crates/pipeline/src/lib.rs` | keep upstream's structure; re-apply the `spatial::open` hook and the resample block |
| `app/src/core/src/state.rs` | keep both sides: upstream's field plus `spatial` in the profile serialization |
| UI screens reorganized again | mount `SpatialStage` in the new profile owner screen; the component itself does not change |

## Verification gates (definition of done)

```powershell
cargo +stable-x86_64-pc-windows-gnu check --workspace
cd app/src/ui; pnpm exec tsc --noEmit; pnpm exec vitest run
python tools/check_lang.py
```

Plus, on the machine that owns the stages: the byte-exact verifier from the engine
repository (`engine/win-port/qa/verify_win_pcm.py`) — a merge that changes the audio path
without that check is not done.

## What must never happen

- Committing feature work on `main`.
- Rebasing or force-pushing `feat/xm6`.
- Hand-editing eight language files instead of merging keys.
- Hand-editing generated bindings instead of regenerating them.
- Shipping a build whose `tools/xm6/STATE.json` does not name the upstream tag it came from.

## State file

`tools/xm6/STATE.json` records where the build came from:

```json
{
  "upstream_tag": "v2.0.2-beta.9",
  "feature_commit": "dfbe3a7",
  "stage_layout": 1,
  "notes": "installed 2026-10-27, GNU toolchain"
}
```

`sync_upstream.py` rewrites it on a successful merge; a build without it is unattributable.
